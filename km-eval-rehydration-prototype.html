Control Plane — Real-Time Eval Rehydration
Evals are the control layer for Knowledge Management. Whenever a gap is detected across any source — a product release, a community thread, a new ADO fix — the matching eval set is rehydrated and re-run automatically, ahead of time, so KM is verified against “what good looks like” before a customer ever asks. This dashboard is the live cockpit for that loop.

Rehydration Pipeline
A closed control loop. Each detected gap spawns a rehydration job: fresh eval cases are synthesized from the triggering source + golden rubric, the KM agents are executed against them, results are scored, and only passing content is promoted. Failing sets open a remediation task and hold the gap in a tested-but-quarantined state.
No active job. Trigger a Product Release, Community Gap, or Run Eval Sweep from the top bar to watch a rehydration job flow through the pipeline in real time.

Multi-Source Eval Fabric
Evals are hydrated from six independent dimensions. No single source defines truth — the golden dataset anchors correctness, while the others supply coverage, recency, and real-world phrasing. Each source is independently monitored for freshness and open gaps, and can be rehydrated on demand.

Gap Radar — Detected Ahead of Time
Gaps are surfaced before they reach a customer by continuously diffing live sources against the KM graph and golden coverage map. Each gap carries a projected lead time (how far ahead of first customer contact we caught it) and an auto-generated rehydration plan.

Agent Drift & Health
Every KM agent is scored on each eval sweep. We track rolling quality, model drift (population stability index on output embeddings), latency and cost. Drift crossing the alert band flags a model for review; crossing the retrain band auto-opens a remediation job.

Golden Baseline — “What Good Looks Like”
The golden dataset is the human-verified contract for a correct answer: expected resolution, required citations, tone, and safety. Every rehydrated eval is scored against these dimension thresholds. A response must clear every gate to be promoted — the white marker on each gauge is the pass threshold.

How the control loop stays honest: the golden set is version-controlled and only expanded through review; rehydrated cases from community / releases / ADO are scored against it, never allowed to redefine it. When a rehydrated case reveals the golden itself is stale (e.g., a new release deprecates a step), it is flagged for golden-set promotion rather than silently accepted — keeping “what good looks like” both current and controlled.
