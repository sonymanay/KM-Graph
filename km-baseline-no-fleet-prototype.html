Why the graph is thin without the fleet

Every capability of the future-vision graph traces back to an agent that continuously feeds it. Remove the fleet and each capability degrades to its manual, static baseline.

CapabilityWith Multi-Agent Fleet (future vision)Without the Fleet (today's baseline)
NodesSymptoms, causes, diagnostics, fixes, evidence, releases, community intents — auto-extracted & entity-resolved.Only what a human hand-authored: a product page and a few KB articles. Causes/fixes never captured as nodes.
Edges / relationshipsTyped, multi-hop: Symptom→Cause→Diagnostic→Fix→Article, with EVIDENCED_BY links.Weak keyword co-occurrence only. No causal reasoning path — the graph is really a flat document list.
ConfidenceEvery cause ranked (e.g. Clock skew 94%), updated as telemetry/cases accrue.None. No signal to rank causes, so diagnosis can't be prioritized.
FreshnessArticles regenerate when code ships or a gap is detected (KB1001 → v2 automatically).Frozen at last human edit (v1, 15 months old). Goes stale silently.
Gap visibility312 recurring queries surface the missing step; content is drafted proactively.Invisible. Gaps are discovered only when customers re-contact — after the fact.
RetrievalHybrid: vector (semantic) ⊕ graph subgraph ⊕ keyword, reranked (RRF).Keyword/BM25 only. Misses paraphrases; returns a whole page, not a diagnosis.
AnswerGrounded, cited, channel-shaped, self-verified.The static article text, identical on every channel, often missing the remediation step → re-contact.
Uncovered queryAuto-drafts a new asset from community + case signal within the loop.“No article found” → escalate to a human; content gap persists for weeks.
Net effect for this use case: the graph holds a product node and a single stale KB1001 (v1). The Clock skew (94%) cause, the w32tm /resync fix, the case evidence, the telemetry link, and the 312-customer demand signal — all shown ghosted above — simply don't exist, because there is no agent to discover, extract, and promote them.
